# ADR-0130：M4 的範圍、回合與開工前的決定

## 脈絡

M3 在 2026-11-12 結束（ADR-0129）。M4「首版」在路線圖上是 `d100-orc`、試翻校準、盲評、發佈流程與著作權律師審查（ADR-0105），結束時 Q-1 到 Q-8 達標、發佈 0.1.0（附錄 B）。第一版的完成條件是公開的 ORC 文件一章，加本機商業書一章，全流程跑完，Q-1 到 Q-8 達標（ADR-0066 第 3 項）。ADR-0129 第 10 項另外交給 M4：譯名的驗證與重送、提示快取、估價的校準、審定的介面與門檻、只補測試的第一個回合、跑的時候看到的小問題。其他 ADR 也有項目等 M4 或試翻：依區塊角色選模型（ADR-0103 第 20 項）、批次併發（ADR-0107 第 4 項）、串流（ADR-0109 第 4 項）、引擎評估（ADR-0113 第 21 項，M3 期間沒有做）。

開工前比對了白皮書、ADR 與程式（`86c494a`）。幾個前提：

* ADR-0028 第 1 項「第一版只做 CLI」、§1.3 的非目標與附錄 B 都把本機介面排在 0.1.0 之後。ADR-0039 的斷言擋下 `src/core/egress/` 以外 import `node:http`、`node:net` 等模組。
* `term_missing` 是逐字比對（`src/core/verify.ts` 的 `textProblems`），重送上限是所有代碼共用的 `MAX_ATTEMPTS = 3`（`src/core/state.ts`），兩個檔都在變異測試的名單裡。
* `src/` 沒有 `cache_control`，M3 收尾兩本書的快取讀寫都是 0（ADR-0129 第 4、5 項）。
* `systems/` 只有 `generic`；CI 的 `test` 工作流程逐一寫出要檢查的規則包，加包要改受保護的 `.github/workflows/test.yml`。
* 沒有發佈的工作流程；`package.json` 是 `"private": true`、版本 `0.0.0`。
* ADR-0127 的斷言要求 `src/cli/run.ts` 不出現 `trial`，加 `--trial` 時要由新的 ADR 處理。

下列 20 項由維護者在 2026-11-12 從問題介面選定，全部照 Manager 的建議。

## 決定

**範圍與順序**

1. 回合循序進行，一個合併、封存之後再開下一個，比照 ADR-0113 第 1 項。
2. M4 的範圍是路線圖的 5 項、ADR-0129 第 10 項交接的全部，加上 `tome status` 指出下一步（第 16 項）。依區塊角色選模型、批次併發、串流與引擎評估排到 0.1.0 之後。
3. **審定介面在 M4、0.1.0 之前做**。修改 ADR-0028 第 1 項：第一版除了 CLI，還有一個審實體卡的本機網頁。審定是不能跳過的關卡（ADR-0055 第 3 項），M3 收尾時 book1 332 筆改 YAML 約 2 小時，還要靠小工具填完（ADR-0129 第 5 項）；第一版就讓每個使用者這樣審，跟「能帶團閱讀的成品」不相稱。校稿、報告與 `overrides` 的介面仍在 0.1.0 之後。
4. 介面的形式是本機網頁，只接受本機位址（`127.0.0.1`）的連線。這是 ADR-0028 第 2 項預留的路，核心本來就寫成函式庫。ADR-0039 的斷言擋的是對外連線；本機伺服器放在指定的模組、只聽本機位址，由那個回合的 ADR 修改斷言。
5. 介面先只審實體卡，留好擴充的結構。盲評要不要用它打分，在盲評的回合開工前再決定。
6. 審定門檻 5 維持；`gender: none` 與跟類別預設相同的代名詞，不再算「有性別或代名詞」。修改 ADR-0119 第 9 項的「照字面算」：book1 出現少於 5 次的 167 筆只因為性別、代名詞或 `keep_source` 進了待人審（ADR-0129 第 5 項），這正是 ADR-0119 第 9 項說要等真的 Pass 0 之後一起調的那一條。實作在審定介面的回合，改之前在 book1 的唯讀複本上量會少審幾筆，只寫數字。

**品質與花費**

7. `term_missing` 的做法先不定。維護者在本機看幾個沒過的單位，分辨是模型用了別的譯名、改了詞形，還是原文那一處不是那個專有名詞；譯名驗證的回合開工前，再從維持逐字比對、只報告、在本機換成鎖定譯名、少送幾次等做法裡選。執行 session 與 Manager 不讀書本內容，只有維護者看得到。
8. 提示快取照 ADR-0036 第 4 項：試翻量到命中率高於損益兩平點才開。試翻的回合一併量命中率。
9. 估價的校準分兩步：先補估價器已知的缺口（每個單位的標籤 token、重送的餘裕），依據寫明是 ADR-0129 第 7 項的量測（ADR-0068），再用試翻校準。
10. ADR-0129 第 10 項的小問題 (a)(b)(e)(f)，跟白皮書、README 停在 M2 的文字，一起放進一個小回合，排在只補測試的回合之後。
11. 第一個回合只補測試，比照 036：`anthropic.ts` 的存活變異、量逾時的設定、Windows 上 `test` 卡住。不動 `src`；Windows 的修法非動 `src` 不可時，停下來問維護者。
12. 引擎評估排到 0.1.0 之後，修改 ADR-0113 第 21 項。`d100-orc` 的素材或收尾的書在分章上卡住時，再提前。

**規則包、盲評與完成條件**

13. `d100-orc` 用哪一份 ORC 公開文件，在那個回合開工前調查授權與雜湊後給維護者選。範圍先做到完成條件那一章用得到的角色、數值塊與詞條。
14. 盲評沿用已定的量（約 100 段、上限 30 美元、1 到 5 分，§8.6），黃金段落只用公開 ORC 文件與公有領域文本，不用商業書。比較的組合與打分方式在盲評的回合開工前定。
15. Q-1 到 Q-8 的判定，修改 ADR-0066 第 3 項的「達標」：
    * `FAILED_QA` 的單位在輸出裡保留原文，不算 Q-2、Q-3 的違規（輸出裡沒有錯的譯名或簡體字），但要列出覆蓋率，在 M4 收尾一起報。
    * Q-4、Q-5 用既有的 H-8、H-5 紀錄（§11、ADR-0098），引擎沒有換就不重量。
    * Q-7 依賴的 H-17 在真的 API 上抓不到中斷的時機，用現有的當機注入測試（`tests/cli/crash.test.ts`），真的 API 標成「未驗證」。
    * 有一項不達標時：Q-1 到 Q-3 修到達標；寫明是初值的 Q-4、Q-5、Q-6、Q-9 用新的 ADR 調；其他延後發佈。
16. 0.1.0 的範圍只多 `tome status` 指出下一步（ADR-0055 的後果本來就要它）。`tome glossary why`、抽圖、`tome restore`、年代與基調、`term_suspect` 的重新設計、依區塊角色選模型都排到 0.1.0 之後。
17. 著作權律師審查由維護者請，時點在功能定案之後、發佈準備的回合之前，讓律師看到最後的行為。範圍至少是「使用者把自己的書送到雲端 API 翻譯」、工具本身的散布與 ORC 的義務；法域與預算由維護者定。結論寫成 ADR，只寫結論。
18. 發佈的工作流程與手動演練在發佈準備的回合做。immutable releases（ADR-0078 第 3 項）與 Trusted Publisher（ADR-0070 第 3 項，設定後 2 天內要首次發佈）由維護者設。0.1.0 發佈之後 schema 不再原地改，要改就升 `/2` 並附遷移。
19. M4 的新相依能手寫就手寫，比照 ADR-0113 第 19 項。審定介面是例外，可以用套件，但每一個仍逐一問維護者，照授權白名單、`npm run licenses`、原生套件審查（ADR-0083）與冷卻期（ADR-0077）。
20. M4 的結束條件照 ADR-0066 第 3 項，比照 ADR-0129：本機商業書用 book1（有 M2、M3 的數據可以比，章節到時再選），公開 ORC 文件用第 13 項選定的那一份的一章，PDF 照 ADR-0112 第 4 項的前例用 pdfkit 鍛造，除非有授權可用的現成 PDF。維護者用自己的金鑰跑，數字寫成收尾的 ADR，只寫數字，不寫書名與內文。

## 後果

M4 有 10 個回合，循序進行。審定介面讓第一版比原本計畫的晚，但每個使用者都要過的關卡不再靠手改上萬行的 YAML。`term_missing` 的做法要等維護者看過原因才定，043 開工前會多一步。快取延到試翻量過才開，M4 前半的翻譯照舊付整個前綴。引擎評估延後，沒有書籤的書照舊用標題建章，平的書籤清單的問題留著。

## 替代方案

**允許回合平行**：共用檔案多，`d100-orc` 也要改受保護的 `test.yml` 與白皮書；**審定介面排到 0.1.0 之後**：第一版的使用者照舊改 YAML；**介面用 Obsidian 外掛或 TUI**：外掛要另外發佈、資料交換的方式沒查過，TUI 有 ADR-0119 否決終端機逐筆問答的同樣顧慮；**門檻照字面算**：低次數的卡只因為有代名詞就要人審；**`term_missing` 現在就定做法**：不知道沒過的原因，選錯會改壞驗證或多花錢；**試翻之前先開快取**：Batch 沒命中時付寫入價，命中率低於約 51% 反而比較貴（附錄 A）；**估價全部等試翻**：已知的缺口要等很久才改；**引擎評估放進 M4**：要在維護者的電腦裝引擎、跑很久，M4 會更長；**依區塊角色選模型放進 M4**：要先有盲評的數據；都否決。
