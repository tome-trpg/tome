# ADR-0113：M3 的範圍、回合與開工前的決定

## 脈絡

M2 在 2026-11-08 結束（ADR-0112）。M3「譯名與輸出」要把「接 Anthropic 翻出一章」推進到「能帶團閱讀的成品」（附錄 B 路線圖）。路線圖列了 11 項：Pass 0、審定、`tome glossary import`、數值塊欄位化、vault、`tome sync`、`tome run`、交付報告、一致性報告、`tome purge`、`tome backup`。另有 6 組項目被 ADR 指到 M3：行內 `runs` 與 `<pc>`（ADR-0092 第 6 項、ADR-0099 第 9 項）、`index` 與 `credits` 的判定（ADR-0092 第 6 項）、放行操作（ADR-0099 第 11 項）、章節判定與 `scan` 改名（ADR-0099 第 12 項）、單書覆寫的額外模式（ADR-0100 第 13 項）、M3 的三項驗證（ADR-0102 第 12 項）。ADR-0111 與 ADR-0112 的 Open Questions 也留給 M3。

開工前比對了白皮書、ADR 與程式（`6b7c6bd`）。幾個前提：

* `book.db` 遷移到第 6 版，還沒有白皮書 §6.3 的 `entity` 與 `render` 表；`series.db` 只有翻譯記憶。
* `src/core/llm.ts` 執行時會讀回覆的 `stop_reason`，`max_tokens` 判成截斷，但沒有存下來。
* Docling 轉接器不輸出 `runs`，IR schema 已有欄位；目前沒有程式抽取圖片。
* 巢狀書籤在 IR 裡完整保留，但 `--chapters` 只看第一層（`chapterMap`）。
* 幾乎每個回合都會改 `src/cli/run.ts`、訊息檔、`src/core/findings.ts` 與 `src/core/store.ts` 的遷移號。

下列 20 項由維護者在 2026-11-08 從問題介面選定，全部照 Manager 的建議。

## 決定

**範圍與順序**

1. 回合循序進行，一個合併、封存之後再開下一個，比照 ADR-0084 第 2 項與 ADR-0099 第 1 項。
2. M2 的重送問題在 M3 的第一個回合處理，排在 Pass 0 之前：M3 收尾還要翻規則書，Pass 0 也會送大量短詞。
3. 請求的切法：字元上限之外，再加每個請求的單位數上限；回覆的 `stop_reason` 存進 `book.db`，才分得出截斷與漏段。上限的數字由那個回合依 ADR-0112 的資料提案。
4. 行內 `runs`（粗體、斜體、連結）在 M3 做，粗體也是 Pass 0 的候選詞來源。
5. `index` 與 `credits` 在 M3 自動判定，判不出來時仍可用 `overrides` 標記。判定規則用維護者的書量過，只寫數字（ADR-0092 第 7 項的做法）。修改 ADR-0092 第 6 項的「不自動判定」。
6. 編輯 `overrides.yaml` 的指令不做，維持 ADR-0092 第 6 項。
7. 章節判定：巢狀書籤在 M3 支援依層級選章節。平的書籤清單（一個章節只是一個小標題）等引擎評估（第 21 項）再定；M2 以「規則多、沒有語料能驗證」否決過的 `heading` 層級推斷，M3 也不做。
8. `scan` 這個頁面類型在 M3 改名，候選名在那個回合開工前給維護者選。
9. S-16（改譯名不重翻全書）在 M3 做，一致性報告的修正靠它。
10. `tome glossary why` 不放進 M3（ADR-0050 定了指令，路線圖沒有排）。
11. 單書覆寫只做 ADR-0100 第 13 項排到 M3 的額外模式；年代與基調之後有需要再加。
12. 數值塊欄位化在 M3 只用合成的測試規則包驗證。H-15 的真實量測等 M4 的 `d100-orc`。

**Pass 0 與實體卡**

13. Pass 0 支援批次與即時，預設批次，跟 `tome translate` 一致。
14. Pass 0 的指令照翻譯指令的前例：放 `prompts/`，指令用英文，維護者逐字審過才接上（ADR-0099 第 27 項、ADR-0103 第 1 項）。
15. 實體卡存 `book.db` 的 `entity` 表。`series.db` 照 ADR-0080 第 4 項只留結構，跨書共用譯名等系列的設計再做。
16. 審定的介面是工作區裡的檔案，格式在那個回合開工前定。vault 做好之後可以加連結。

**vault 與輸出**

17. vault 裡給人看的固定文字放 `src/cli/messages/zh-TW.json`，跟 CLI 文字同一套規則（ADR-0082 第 9 項，核心只回代碼）。
18. vault 的檔名用「編號加章名」，在 Obsidian 才好找。書名與章名是書本內容，所以 CLI 的訊息、紀錄與 `--json` 只印 vault 的根目錄與數量，不印個別檔案的路徑（ADR-0059 第 5 項）。vault 在使用者的電腦上，照舊 MUST 位於任何 git 儲存庫之外（ADR-0053 第 2 項，`tome init --vault` 已經用 `vault.in_git_repo` 檢查）。
19. M3 的新相依能手寫就手寫，比照 ADR-0084 第 14 項。真的需要套件時逐一問維護者，照授權白名單、`npm run licenses`、原生套件審查（ADR-0083）與冷卻期（ADR-0077）。
20. M3 的結束條件比照 ADR-0099 第 29、30 項：用 `tome run` 把公有領域的文本與維護者的規則書一章跑到 vault，花費、估價誤差、拒答、`FAILED_QA` 與譯名的數字寫成 ADR，只寫數字，不寫書名與內文。M3 收尾的 ADR 寫完才算結束。

**回合與其他**

21. 引擎評估（OpenDataLoader 等開源引擎，硬條件是開源、安全、免費）在 M3 期間進行，不改 repo，可以跟任何回合同時做。要在維護者的電腦上安裝或執行引擎、要不要接受 Java 等前置條件，開始前再問。第 7 項平的書籤清單等它的結果。
22. 回合的草案如下，編號接在 024 之後。每個回合開工前照 M2 的做法，把細節列成問題給維護者：

    | 回合 | 範圍 |
    | :--- | :--- |
    | 025 | M2 的修正：存 `stop_reason`、單位數上限（第 3 項）；範圍內與整本書的單位數說法；`tome add` 多餘參數的訊息 |
    | 026 | 文件結構：行內 `runs` 與 `<pc>`（第 4 項）；`index`、`credits` 判定（第 5 項）；巢狀書籤選章節（第 7 項）；`scan` 改名（第 8 項）；放行操作的格式 |
    | 027 | 實體卡與 Pass 0：`entity` 表、`tome scan-terms`、`scanner_model`、全書提要、活躍實體進請求（第 13–15 項） |
    | 028 | 審定與詞庫：`tome glossary review`、`import`、`<new-term>` 進佇列、S-16（第 9、16 項） |
    | 029 | 數值塊欄位化與合成測試包（第 12 項），排在 025 之後、030 之前 |
    | 030 | vault 與報告：`tome assemble`、`render` 表、交付報告與 `tome report`、一致性報告、M3 的三項驗證、額外模式（第 11、17、18 項） |

    `term_suspect` 誤報（ADR-0111 的 Open Question）要不要獨立一個小回合，排在 030 之前再問。
23. 下列細節等各回合開工前再問，比照 M2 的 ADR-0100 到 ADR-0104：`tome run` 停在關卡時的結束碼與 `--trial`；`vault_path` 沒設時的處理；`assets/` 的圖片怎麼抽；vault 的 `review/` 與 `tome preview` 的關係；`tome report` 是否只給數字；一致性報告的偵測方法與是否獨立成檔；人工譯文要不要跑零 token 驗證；`tome purge` 的確認方式；`tome backup` 的範圍、格式與個資清單要不要進備份；外送紀錄的保留期（ADR-0104 的 Open Question）。

## 後果

M3 有 10 個回合，循序進行。每個回合都要等前一個合併，速度比平行慢，但不會撞共用檔案與遷移號。章節判定只解決巢狀書籤，平的書籤清單要等引擎評估。vault 用章名當檔名，訊息因此不能印個別檔案的路徑，使用者要自己到 vault 找。

## 替代方案

**允許回合平行**：共用檔案讓能平行的組合很少；**重送問題併進 Pass 0 或等 M4**：規則書每翻一次多約 15%；**只依單位數切請求**：費用與 token 上限就沒人管；**`runs` 與 `index` 延後**：輸出沒有粗體斜體，索引照樣送翻譯；**做 `overrides` 的編輯指令**：ADR-0092 已經否決；**推斷 `heading` 層級**：M2 否決過，仍沒有語料能驗證；**S-16 延後**：改一個譯名就要重翻；**`d100-orc` 提前到 M3**：範圍太大；**實體卡同時寫 `series.db`**：跨書共用要先有系列的設計；**審定放 vault**：vault 排在審定之後；**vault 只用編號當檔名**：在 Obsidian 不好找；**用套件取代手寫**：每個都要過授權與冷卻期；**只用公有領域收尾**：ADR-0112 已經否決；都否決。
