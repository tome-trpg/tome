# ADR-0112：M2 收尾與真實翻譯的數字

## 脈絡

ADR-0099 第 29、30 項定了 M2 的收尾：第一次真實翻譯先用公有領域文字鍛造的 PDF，再翻維護者的商業書一章，花費、估價誤差、拒答與 `FAILED_QA` 的數量寫成 ADR，只寫數字，不寫書名與內文。寫完 M2 才算結束。

M2 的回合 015 到 024 都已合併。2026-11-07 到 2026-11-08，維護者用自己的金鑰在自己的電腦上跑了 `tome provider test` 與兩次真實翻譯。下面的數字由 Manager 唯讀維護者的 `book.db` 與 `document.json` 算出，只輸出數字，沒有讀商業書的內文。

## 決定

1. ADR-0099 第 29、30 項完成，M2 到此結束，下一個階段是 M3。
2. 個資清單 `pii` 是空的時，`tome estimate` 與 `tome translate` 維持只警告（`pii.empty`），不擋下。維護者在 2026-11-08 看過商業書那次的情形後決定：那次清單是空的，個資閘門什麼都沒檢查，事後計數也沒有找到維護者的個資（第 5 項）。
3. `tome provider test` 的結果（2026-11-07，`8cbaf93`）。這是 TOME 第一次對真的 API 發請求，只查 Models API，沒有消耗 token。四個模型都是 `provider.tested`，Models API 回報的欄位都不是空值，每一項都有比對：

   | 模型 | 批次 | `thinking.disabled` | `thinking.between_tools` | 伺服器端回退 | 淘汰日期 |
   | :--- | :--- | :--- | :--- | :--- | :--- |
   | `claude-opus-5-5` | 是 | 否 | 否 | 是 | 無 |
   | `claude-sonnet-5-5` | 是 | 否 | 是 | 是 | 無 |
   | `claude-haiku-5-5` | 是 | 是 | 否 | 否 | 無 |
   | `claude-fable-5-1` | 是 | 否 | 否 | 是 | 無 |

   ADR-0103 第 6 項與 ADR-0109 的 Open Question「Opus 5.5、Fable 5.1 的伺服器端回退」因此結案：兩者的 `allowed_fallback_models` 都不是空的，跟 `providers/anthropic.yaml` 的 `fallback.server: true` 一致。這是供應商回報的能力，TOME 不用伺服器端回退（ADR-0104），實際回退的行為沒有測過。
4. 公有領域的翻譯（2026-11-07，`8cbaf93`）：
   * 素材：Project Gutenberg 第 68283 號 The Call of Cthulhu 的純文字版（1928 年刊於 Weird Tales，美國已進公有領域），SHA-256 `db20dc8b4b2a58af9462c2f66d3deefa843c3bce4390b825f74d31ca231eedca`。Manager 用 pdfkit 鍛造成 20 頁的單欄 PDF，SHA-256 `4f24b7d6260f0593e4a8151a47301c9388b026da363e99a263380537493f7b74`，同樣的輸入產出相同的檔案。PDF 與原文都不進 repo，所以不登記在 `tests/fixtures/SOURCES.yaml`（ADR-0061 的清單只管 repo 裡的素材）。
   * 設定：Sonnet 5.5、批次、預算 $1.00。
   * 結果：127 個翻譯單位，其中 10 個不需翻譯（場景分隔）。完成 126，個資閘門 0，`FAILED_QA` 1（`too_short`，下限當時是 0.3），拒答 0。
   * 花費 $0.1924，估價 $0.16 至 $0.26：第一輪 $0.1858，重送 $0.0066。3 個批次，每批送出到收回 1 到 3 分鐘，遠端資料都刪了。
5. 商業書一章的翻譯（2026-11-08，`9dcb198`）：
   * 素材：維護者自有的一本規則書，110 頁。解析沒有字元守恆的警告，document 層 1,723 個區塊、174 個章節。
   * 範圍：`--chapters 1-172`，PDF 第 3 到 108 頁（第 1、2 頁在第一個書籤之前，選不到）。
   * 設定：Sonnet 5.5、批次、預算 $2.00，個資清單是空的。
   * 結果：範圍內送出 2,274 個翻譯單位，另有 276 個不需翻譯。完成 2,551（含原樣保留），個資閘門 0，`FAILED_QA` 9（`script_mixed` 5、`too_short` 4），拒答 0。範圍外的 19 個單位沒有送出。
   * 花費 $1.1047，估價 $0.68 至 $1.10，**比上限多 $0.0047**：第一輪 174 個請求 $0.9357，落在區間的 61%；重送 33 個請求 $0.1691。5 個批次，每批送出到結束 1.5 到 3.6 分鐘，遠端資料都刪了。
   * 重送很多：送出的 2,274 個單位，1,757 個送 1 次、110 個送 2 次、407 個送 3 次。其中 497 個被計費多次卻只有 1 筆回應，表示所在的請求有回覆、有計費，回覆裡卻沒有它的段落，只能整組重送。最大的請求有 230、161、152 個單位，多是表格裡的短格子。`book.db` 沒有存回覆的 `stop_reason`，無法確定是截斷還是漏段（Open Questions）。
   * 個資：清單是空的，閘門沒有檢查任何東西。Manager 事後計數，document 層與送出的單位都不含維護者的姓名、email，也不含 `order #`、`purchased by`、`DriveThru`、`licensed to` 這類購買浮水印的字眼；document 層沒有 `furniture` 區塊。訂單編號沒有查。
6. 估價誤差的第一筆數據：第一輪的花費都在估價區間內（26% 與 61% 處），超出的部分來自重送。估價的比例仍標成「未校準」，兩次都是 Sonnet 5.5、批次，其他模型與即時模式沒有數據。

## 後果

TOME 已經用真的 API 走完整條流程：金鑰、對外出口、批次的建立、輪詢、`results_url` 下載與刪除。ADR-0109 的 Open Question「`results_url` 的主機」因此結案，兩次翻譯的結果都從白名單內的主機下載。H-17（當機後用 `list` 認回批次）沒有走到，仍未驗證。

H-4 有了第一筆數據：Sonnet 5.5 翻 The Call of Cthulhu 117 個單位，拒答 0。只有一篇、一個模型，還不能說各家的拒答率。

規則書的短格子讓請求的單位數暴增，重送多了約 15% 的花費。M2 收尾時沒有修，列在 Open Questions，交給 M3 決定。

## 替代方案

**個資清單是空的就擋下翻譯**：比較安全，但沒有購買浮水印的書也必須先填清單；維護者選了維持只警告。**只用公有領域的翻譯收尾**：規則書的表格與短格子不會出現，重送的問題就看不到；否決。**把書名或內文寫進紀錄**：違反 ADR-0099 第 30 項；否決。

## Open Questions

- [ ] 規則書的重送：497 個單位所在的請求有回覆卻沒有它們的段落。要存回覆的 `stop_reason` 才能確定是截斷還是漏段，也要評估每個請求的單位數上限，或依單位數而不是字元數切請求。
- [ ] `translate.done` 與 `tome status` 的總數與「不需翻譯」是整本書的數字，估價只算範圍內；範圍外沒送出的單位被算成「尚未完成」。說法要再對齊。
- [ ] 章節的判定：這本規則書的書籤是一份平的標題清單，174 個章節都在第一層，一個章節只是一個小標題；The Call of Cthulhu 的三章掛在書名底下，被當成一章（ADR-0092 只取單層）。`--chapters` 很難照書的章節選。
- [ ] `tome add` 收到多餘的參數時只回「參數不正確」，沒有說是哪一個；路徑有空格沒加引號時，使用者看不出原因。
- [ ] `min_length_ratio` 0.2 在規則書仍有 4 個 `too_short`，`script_mixed` 有 5 個，都沒有看過原因（ADR-0111 的 Open Question 延續）。
- [ ] 估價比例的校準：只有 Sonnet 5.5、批次的兩筆數據。
