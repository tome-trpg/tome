# ADR-0081：讀者測試後的修正

## 脈絡

第 9 輪用沒看過討論的新讀者測試白皮書，並審查全部文件，找到幾個設計缺口。譯後排版可能動到還原後的骰子，預算的硬上限沒有定義，翻譯記憶在 0.1.0 沒有地方放，個資閘門有三種說法。這份 ADR 記下修正與維護者的決定。

## 決定

**預算**

1. 預算以書為單位累計，從第一筆付費呼叫就生效，Pass 0、試翻、重試、回退全部計入。
2. 每次送出前檢查：已花 + 進行中的估價 + 這次的估價 ≤ 預算。超過就不送，用 `--budget` 提高上限後續跑。
3. 估價確認的關卡在主翻譯之前。Pass 0 與試翻在關卡之前，但都顯示自己的估價。

**個資**

4. Pass 0 與主翻譯都一樣：送出前掃描整批，命中就整批不送並停下，有單位的標成 `BLOCKED`，等使用者處理後續跑。沒處理的 `BLOCKED` 單位輸出時不放原文。
5. 這個功能叫個資過濾，跟遮蔽是兩件事。

**人工譯文與失敗段落**

6. 鎖定譯名改動時，人工譯文不替換，內含舊譯名的段落列入交付報告。
7. `FAILED_QA` 與 `REFUSED` 的單位輸出時保留原文，放在 `[!untranslated]` callout，並列入交付報告。

**翻譯流程**

8. 譯後自動排版在還原之前執行，佔位符不受影響。
9. `translate` 包含驗證與重送。`tome verify` 用存下來的原始回應重跑驗證，不花 token。
10. `--chapters` 選擇要翻與輸出的章節，解析與 Pass 0 仍跑全書，譯名才會一致。
11. 翻譯記憶與人工譯文存在 `series.db`，每本書預設自成一個系列，跨書共用排到 0.1.0 之後。
12. 分清單位、請求、批次三個層級。請求的 `usage` 依字元數分攤到單位。

**範圍**

13. 0.1.0 只處理原生文字頁，掃描、壞文字層與純圖片的頁面不翻，列入交付報告。
14. LLM 校稿排到 0.1.0 之後，ADR-0013 的原則維持。
15. 正式支援 Windows 與 Linux，macOS 盡力而為。

**其他**

16. `fallback_model` 選填，沒設就標成 `REFUSED`。
17. 存金鑰的指令是 `tome provider auth set`，取代 ADR-0034 的 `tome auth set`。
18. DC-2 的開關放在單書設定。Gemini 看不出金鑰層級，要使用者宣告付費層才放行。
19. 有刪除 API 的供應商才要求刪除，沒有的在估價時警告。
20. 單一對外出口限主程式。安裝解析引擎時的下載是唯一例外。
21. 有單位之後的階段狀態由單位推導，還沒有單位的階段記在 `stage`。
22. 區塊 ID 只放在連結目標上，完整對應表放在 `review/`，取代 ADR-0005 的「保留區塊 ID」的直接寫法。
23. 文件 MUST 說明 TOME 是給使用者處理自己擁有的書，譯文不得散布（PC-5）。
24. 專案最初的 prompt 不放進 repo，規格都寫進文件。

## 後果

白皮書升到 1.0.0。ADR 裡提到的 prompt 只是歷史脈絡，規格以白皮書為準。

## 替代方案

各項的替代方案在第 9 輪討論時都考慮過：**每次執行分開算預算**會讓總花費超過以為的上限；**個資命中只擋單一段落**可能漏掉同樣的漏洞；**自動替換人工譯文**會改到使用者刻意的寫法；**放最後一次的譯文**可能帶著錯誤的數字；**校稿進 0.1.0** 會讓首版變晚；都否決。
