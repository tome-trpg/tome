# 046 — d100-orc 規則包

## Intent

這個回合結束時，TOME 附第二個內建規則包 `d100-orc`，依 Chaosium 的 Basic Roleplaying ORC Content Document（ORC 授權）寫成，範圍是維護者選定的那一章用得到的數值塊角色與詞條：數值塊宣告 `fields` 與 `detect`，整塊對得上的在本機翻好。規則包附 ORC License 全文與照 Chaosium 寫法的聲明，署名「TOME 的貢獻者（TOME contributors）」。這份 PDF 下載到 repo 外、登記在 `tests/fixtures/SOURCES.yaml` 的外部素材段，用不連網的本機工具驗證雜湊；H-15 由手動觸發的 workflow 在 GitHub runner 上解析整份文件量出數字，本機商業書另外量、只記數字。它讓 050 的全流程有公開的那一章可以跑，也第一次在真書上量 H-15（ADR-0130 第 13、21 項，決定寫成 ADR-0136）。

## Negative Scope

* repo 不放這份文件本身、整段原文、譯文或截圖；只放照 ORC 授權衍生的規則包內容（ADR-0061、CLAUDE.md 不可違反第 1 項）。
* 不參考任何官方中文版的詞表，譯名自己擬（PC-1）。
* 不做法術、超能力、世界設定與那一章用不到的角色與詞條；商標與世界設定的專有名詞不收進詞條。
* 不放「Powered by BRP」標誌或任何圖檔。
* 不讀 `C:\Repos\tome-books` 底下商業書的內文；量 H-15 只用唯讀暫存複本、只印數字、量完刪掉。
* 不呼叫 LLM API，不花錢；章節的估價只在本機算。
* 主程式不加連網的路，驗證雜湊的工具不連網（ADR-0039）。
* 不在維護者的筆電上跑長時間吃滿核心的解析；整份文件的解析在 GitHub runner 上跑。

## Not Empowered

* `src/**` 的程式、提示、供應商設定、schema 與 `generic` 規則包；需要改它們時先停下來問。
* 譯名與進提示的文字（角色的 `style`、`persona_and_tone.md`、`few_shots.md`）在維護者審過之前不 commit。
* 用哪一章由維護者定；下載後先回報各章的數字。
* 改 `.github/workflows/` 的推送被拒時停下來回報，不繞過。
