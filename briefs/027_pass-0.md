# 027 — 實體卡與 Pass 0

## Intent

這個回合結束時，`tome scan-terms <book>` 會在本機從索引、標題、粗體與大寫片語挖出候選詞，每個帶最多兩句、每句最多 200 字元的上下文，送給 `tome.yaml` 的 `scanner_model`，拿回譯名、類別、性別、代名詞、語域與是否保留原文的**提議**，存進 `book.db` 新的 `entity` 表；同一批也從目錄與開頭產出英文的全書提要，存進 `summary` 表。它跟翻譯走同一條路：預設批次、`--realtime` 即時，不加 `--confirm` 只估價，確認時比對內容指紋，花費計入同一份預算，個資閘門、外送紀錄與帳本都一樣。兩份新提示 `prompts/scan-terms.md`、`prompts/summary.md` 照維護者審過的文字接上。

細節由維護者在 2026-11-08 選定（共用筆記 `brief-027-questions.md` 的 15 項），寫成 ADR-0118。實體卡與提要進翻譯請求拆到回合 037，排在 028 之後。

## Negative Scope

- 不做實體卡與提要進翻譯、活躍實體、`keep_source` 實體卡的遮蔽、翻譯記憶與譯名驗證加上實體卡、`prompts/translate.md` 的改動（037）。
- 不做審定、`tome glossary import`、`<new-term>` 進佇列、分級審定的規則（028）。
- `series.db` 只照 ADR-0080 第 4 項留結構，不做跨書共用（ADR-0113 第 15 項）。
- 不做日文的候選詞挖法。
- 不對真的 API 發請求，只跟假供應商跑。
- 不寫入維護者的工作區，不在他的電腦上跑整本解析。
- 不放商業書的內容，範例與測試都用合成文字；量到的數字不寫書名，不印候選詞與譯名。

## Not Empowered

- ADR 沒寫到的選型、命名、範圍、政策不能自己定，要先問 Manager。實作時冒出的新細節寫進共用筆記 `brief-027-details.md`。
- 兩份提示的文字照審過的草稿，要改字就是新的提示審查，先問。
- 寫給維護者的理由要先對照程式與 ADR 原文。
- 核心不放給人看的文字，也不放語言相關的字詞；訊息照 ADR-0086、ADR-0089。
- 成熟度照實寫：候選詞的規則與請求的數字都是提案。
- 公開文件寫「維護者」，不寫人名。
- 檔案用 Write 與 Edit 改，不用 Bash 或腳本繞過寫入掛勾。
- 不合併，也不自己封存。CI 第一次跑完全綠就回報 Manager，等審查說可以封存才在回合分支上封存。

## Measured

2026-11-08（UTC），Windows 參考機器。

**候選詞的量測**：開工前用原型、實作後用實作的規則，各在 `book1` 的 `document.json` 複本上挖一次，只印數字，跑完刪掉複本，只讀維護者工作區的 `book.yaml` 與規則包，沒有寫入。實作後：候選詞 744 個（標題 156、大寫片語 632），21 個請求，實際送出的詞與句子 78,475 字元，占全書文字的 31.0%；加上提要的輸入最多 33.3%。數字寫在 ADR-0118。

本機結果：`npm test` 65 個測試檔通過、1 個跳過，1,655 個測試通過、5 個跳過；`npm run spec` 291 個斷言都成立，也都看過失敗；`npm run licenses` 299 個套件沒有違規。
